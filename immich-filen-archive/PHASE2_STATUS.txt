Architecture review after pilot:
The transparent path-preserving tier works, but it requires a custom Immich delete integration and therefore is not the preferred long-term maintenance-free architecture.

Official External Library migration proof:
- production database cloned into an isolated PostgreSQL test environment
- four production users tested independently
- one representative Tier-1 asset per user
- normal External Library import assigned all four assets to the correct owners
- normal import created new asset IDs and did not preserve album/face relations automatically
- one-time ID-preserving conversion was then tested on the isolated DB clone
- original asset IDs were retained for Daniel, Cindy, Maja and Emily
- ownerId remained correct for all four
- existing album memberships remained intact
- existing face links remained intact where present
- assets remained isExternal=true and attached to the intended official External Library
- an official library rescan did not recreate duplicates
- a real read-only Filen/rclone-mounted file was imported successfully into an official External Library
- ffprobe through that official External Library path passed

Remote-unavailability proof:
- when the isolated Filen path was hidden and an official library scan was queued, the existing external asset was NOT deleted immediately
- Immich marked it isOffline=true and set deletedAt
- after the Filen path was restored and the library rescanned, the SAME asset ID returned to isOffline=false and deletedAt=null
- therefore short remote outages are recoverable by official scan semantics

Critical long-term safety finding:
- the cloned production configuration currently has library.watch.enabled=true
- Immich v3.2.1 file-watcher unlink events queue LibraryRemoveAsset, which removes the asset row directly
- automatic/manual scans mark inaccessible external assets offline and set deletedAt
- AssetDeleteCheck later selects assets by deletedAt; after trash retention expires an offline external asset can therefore be removed from the database even when the remote backend was only unavailable
- Immich defaults library.watch.enabled=false, but this installation currently overrides it to true

Required maintenance-free production contract:
1. official External Libraries only; no permanent custom Immich image after migration
2. exactly four libraries, one owner each: Daniel, Cindy, Maja, Emily
3. library.watch.enabled=false before any production External Library is created
4. built-in automatic library scan disabled for Filen-backed libraries
5. scans triggered only by a small systemd-gated safe-scan service/timer after a positive Filen/rclone health probe
6. if the probe fails: NO scan, alert, leave database untouched
7. mount/watchdog failure must be fail-closed; stopping Immich is preferred over allowing an unsafe scan
8. one-time ID-preserving migration must run only after full DB backup and rollback proof
9. safe-scan/API failure must alert and keep data safe; it must never silently fall back to an ungated scan

Tier-1 metadata impact if plain re-import were used:

- 385 face links
- 0 stacked assets in this Tier-1 set

New preferred direction:
Use official Immich External Libraries for long-term operation, combined with a one-time, fully backed up, ID-preserving migration of existing assets. This removes the need for a permanent custom Immich delete patch after migration.

Still required before production migration:
- implement and test the gated safe-scan service/timer
- prove watcher disabled + built-in scan disabled
- broader invariant checks including favorites, albums, faces/persons, shared links and derived files
- complete rollback contract and database backup
- restore the current one-file COLD_ACTIVE pilot to HOT_LOCAL before final architecture cutover

Kritische Langzeit-Sicherheitsfeststellung:

- automatische/manuelle Scans setzen bei nicht erreichbaren External Assets isOffline=true und deletedAt

- Immich hat library.watch.enabled standardmäßig false, diese Installation überschreibt das derzeit jedoch auf true
